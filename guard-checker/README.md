# guard-checker — проверяющий себя не правит

Событие: **PreToolUse**, инструменты записи файлов.
Команда: `wk hook guard-paths`.
Действие: путь из `tool_input.file_path` совпадает с защищённым — **код 2**, одна строка причины.
Иначе код 0.

## Защищённые пути

| путь | причина |
|---|---|
| `docs/_meta/check.py` | проверяющий инструмент не правится тем, кого он проверяет |
| `.claude/settings.json` | там живут сами хуки |
| `.codex/hooks.json` | там живут сами хуки |
| `.wiki-project.yaml` | оттуда хуки берут, что защищать |
| `flake.nix`, `flake.lock`, `.envrc` | закрепляют версию `wk`, которую вызывают хуки: иначе проверяющий подменяется |
| `.github/workflows/wk.yml` | CI-гейт с закреплённой версией `wk`: последняя защита, которую агент не обходит |

Первые два были в требованиях с самого начала, остальные добавлены потому,
что без них защита снимает себя сама.

`.codex/hooks.json` — точный аналог `.claude/settings.json` для второго харнесса:
без него на codex достаточно удалить собственный конфиг.

`.wiki-project.yaml` — на уровень глубже. `guard-block` берёт список защищаемых файлов
из `policy_blocks` манифеста, `policy-stale` и `check` — параметры компиляции. Манифест
без защиты это выключатель всех трёх: стёр `policy_blocks`, и блок политик стало можно
править. Ничего не ломает: манифест пишет только `wk init`, минуя инструменты харнесса.

`.claude/settings.local.json` **не** защищается: это личные настройки человека, вне git.

После задачи 06 `check.py` в проекте не нужен вовсе — хук остаётся страховкой от его возвращения.

## Границы

Файлы, не перечисленные в таблице, не блокируются. Хук не редактирует файлы,
не обращается к сети и ничего не печатает, кроме причины отказа.
