# guard-policy-block — блок политик неприкосновенен

Событие: **PreToolUse**, инструменты записи файлов.
Команда: `wk hook guard-block`.
Условие: целевой файл перечислен в `policy_blocks` манифеста `.wiki-project.yaml`.
Действие: правка затрагивает строки между `<!-- wikisvc:begin` и `<!-- wikisvc:end -->` → **код 2**.

Текст отказа, одна строка:

> Блок политик генерируется. Измени правило в вике: `wk propose`, затем `wk policy sync`.

Файл не из `policy_blocks` — код 0, молча.

## Откуда хук берёт путь к файлу

Из JSON на **stdin**, поле `tool_input.file_path`. Не из аргументов команды.

Подстановки значений payload в аргументы команды нет ни у одного из двух харнессов:
claude-code поддерживает `${...}`-подстановку только для хуков типа `mcp_tool`, а не `command`;
codex передаёт команде тот же JSON на stdin. Чтение stdin — единственный переносимый вариант,
и он же единственный работающий. Зафиксировано в `../../fix.md`, раздел A1.

Общие поля stdin у обоих: `session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`.
Хук обязан игнорировать неизвестные поля: состав payload у харнессов различается и растёт.
Payload без `tool_input.file_path`, с лишними полями или обрезанный — код 0 и пустой вывод,
без падения.

## Matcher

Строка `Edit|Write|MultiEdit|NotebookEdit` корректна в обоих, но по разным правилам:
в claude-code это точный список через `|`, в codex — незаякоренное регулярное выражение.
Результат совпадает, поэтому строка общая. Менять её на регулярное выражение с якорями
нельзя: claude-code тогда перейдёт в режим regex и поведение разъедется.
