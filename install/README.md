# install — собранные конфигурации

Папки хуков выше — источник по одному хуку. Здесь они собраны в файлы, которые
раскладывает `wk init`: в проекте не может быть четырёх `settings.json`.

| файл | куда | что внутри |
|---|---|---|
| `claude-settings.json` | `.claude/settings.json` | `guard-paths`, `guard-block`, `policy-stale`, `check` |
| `codex-hooks.json` | `.codex/hooks.json` | то же |

Два хука записи сведены в одну группу `PreToolUse` с общим matcher: у обоих харнессов
несколько команд в одной группе выполняются вместе, и достаточно кода 2 от любой,
чтобы запись была заблокирована.

Гейт на остановке вызывает `wk hook check`, а **не** `wk check --strict`: блокирует
только код 2, а прямая команда даёт 1 при ошибках и 3 без сети. Подмена превращает
гейт в украшение. Таблица отображения кодов — в `../check-on-stop/README.md`.

`timeout` 10 у `policy-stale` и `check`: обе обращаются к вике за версией блока политик.
У хуков записи 5 и сети нет вовсе.

Существующий `.claude/settings.json` или `.codex/hooks.json` `wk init` не перезаписывает:
печатает diff и предложение применить руками.

Подкоманды `wk hook` пока нет — её делает задача 04. До неё эти файлы можно разложить
без риска: неизвестная команда даёт код 1, который ни на одном из трёх событий
не блокирует, только пишет строку в stderr.
